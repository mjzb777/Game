# Dubai Drive

A driving game in Godot 4 (GDScript) set in five real Dubai districts built from
OpenStreetMap data: Mirdif, Downtown, Jumeirah, Umm Suqeim and Oud Metha.

Current scope: steps 1 and 2 (world and driving, then missions). There is no traffic,
no tickets and no visual polish yet.

## Quick start

Requirements: Godot **4.5** (4.3+ should work) and Python 3.8+ (standard library only).

```bash
# 1. Download OSM data for all 5 districts (needs internet access to overpass-api.de)
python3 tools/fetch_osm.py

# 2. Match mission places against the downloaded data and write the report
python3 tools/resolve_missions.py

# 3. Run the game
godot --path .
```

Open `data/place_verification.md` after step 2. It lists every mission place, the OSM
element it matched (id and coordinates), and any place that could not be verified.

## Controls

| Key | Action |
|---|---|
| W / Up | Accelerate |
| S / Down | Brake, then reverse |
| A, D / Left, Right | Steer |
| Space | Handbrake |
| M or Tab | Mission list (start or cancel a mission) |
| Enter / E | Advance NPC dialogue |
| F | Refuel (stop at a red petrol-station block) |
| R | Put the car back on the nearest road (and give 5 L if the tank is nearly empty) |
| Esc | Pause / main menu |

## What to test

1. **Menu.** All 5 districts are listed with "x/10 missions". Pick one; only that district loads.
2. **World.** The roads are dark ribbons (major roads darker), the buildings are gray
   blocks (OSM height or levels × 3.2 m), the ground is sand, and petrol stations are
   red blocks. Compare the layout with a real map; north is "up" (-Z).
3. **Driving.** The car accelerates to about 90 km/h in 3 s, with a top speed of
   about 155 km/h. It steers, brakes and reverses. Buildings block the car, but roads
   are never blocked. The camera follows behind. The speedometer (bottom right) shows
   km/h. The road name and its OSM speed limit appear bottom left.
4. **Fuel and money.** The fuel bar drains as you drive. At a petrol station, stop and
   press F: fuel costs AED 3/L and comes out of your wallet. New saves start with AED 200.
5. **Missions.** Press M and start one. The NPC intro dialogue plays. Then check:
   - the yellow beam (blue for a pickup) in the world,
   - the GPS arrow and distance at the top,
   - the timer on timed missions (red under 10 s),
   - on speed-limit missions, going over the limit for more than 1 s fails the mission.
   On arrival you get the completion dialogue and a reward popup.
6. **Saving.** Complete a mission, quit and restart. The money and "[done]" marks
   persist (`user://save.json`). Replaying a mission pays 25% of the reward.
7. **Failure cases.** Let a timer run out, speed on a speed-limit mission, cancel a
   mission from the list, run out of fuel, then press R.

## Automated checks

```bash
godot --headless --path . --import                              # first time only
godot --headless --path . -s res://tests/check_scripts.gd      # every script compiles
godot --headless --path . res://tests/test_runner.tscn         # 75 gameplay checks
python3 tests/test_tools.py                                    # OSM conversion + place matching
```

`test_runner.tscn` loads every real district scene and data file. It drives the car,
runs all four mission types, and tests fuel and saving on a **synthetic** test map in
`tests/fixtures/`, which is test data only and not real OSM data.


## Adding a district (data only)

1. Add `data/districts/<id>.json` with `id`, `name`, `bbox` (south/west/north/east,
   about 2–3 km), `spawn` (lat, lon, heading_deg) and `missions`. The car is moved to
   the nearest road automatically.
2. Run `python3 tools/fetch_osm.py <id>`, then `python3 tools/resolve_missions.py`.

The menu finds the new file on its own. A scene in `scenes/districts/<id>.tscn` is
optional; without one, the generic `scenes/district.tscn` is used.

## Mission format

```json
{
  "id": "dt_02", "type": "delivery",
  "title": "Opera Night", "description": "Pick up {item} at {pickup} and deliver it to {dropoff}.",
  "npc": "Khalid",
  "dialogue": {"intro": ["..."], "complete": ["..."]},
  "reward": 400,
  "item": "a bouquet of flowers",
  "pickup":  {"names": ["The Dubai Mall", "Dubai Mall"], "categories": ["shop=mall"]},
  "dropoff": {"names": ["Dubai Opera"], "categories": ["amenity=theatre"]},
  "time_limit": 120,
  "speed_limit_kmh": 50
}
```

- **Types.** `drive_to` (`target`), `delivery` (`pickup` → `dropoff`), `timed`
  (`target` + `time_limit`) and `speed_limit` (`target` + `speed_limit_kmh`).
  `time_limit` is optional on any type.
- **Places.** Each place lists the names it is known by. `resolve_missions.py` looks
  them up in the OSM data and writes `"resolved": {osm_id, name, lat, lon}` into the
  file. Coordinates always come from OSM and are never typed in by hand.
  - With `"allow_fallback": true`, an unmatched place uses the nearest real OSM place
    of a listed category. The text then shows that place's real name through the
    `{target}`/`{pickup}`/`{dropoff}` placeholders.
  - A mission whose place is unresolved is shown as unavailable.
- **Markers.** In the game, markers snap to the nearest road (within 300 m) so the
  car can reach them even when the place is inside a building footprint.

Run `python3 tools/resolve_missions.py --list-pois downtown --grep mall` to browse real
place names when writing or fixing missions.

## Data notes

- Map data © OpenStreetMap contributors, ODbL.
- The district bounding boxes and spawn points (3 × 3 km around each district
  centre) were set by hand from approximate centre coordinates. Adjust `bbox` and
  re-run the fetch if a district should be framed differently.
- To export the game, add `*.json` to the export preset's non-resource filter so the
  data files are included.
